# Pi setup

Setup guides for the global Pi configuration under `~/.pi/agent/`:

- [Pi agents](pi-subagents.md) — pi-subagents setup, parent workflows, and migration validation.
- [Parent workflow commands](pi-custom-commands/README.md) — `/plan`, `/architect`, and `/normal`.
- [Guardrails](pi-guardrails/README.md) — scout search delegation and commit protection.

From this repository:

```powershell
node install.mjs --dry-run
node install.mjs
```

The installer backs up live configuration, installs pi-subagents and the local
extensions, deploys agents, merges workflow instructions/settings, and then runs
`pi uninstall npm:pi-open-agents`. Review the dry-run output before installation.
It preserves unrelated settings and extra agent files; it never copies the full
`.pi.user/settings.json` template over live settings.

A genuinely new installation (no target `settings.json` before installation)
queues Claude as the first-start default. The first idle interactive Pi startup
applies it through `/profile claude` after subagents are ready. Model selection
remains version-independent and subject to the scoped model list and credentials.
If setup cannot complete, `/profile` shows the pending default; authenticate and
run `/profile claude` to finish. Any existing settings file keeps its defaults and
selected profile, including when no profile is currently selected.

The instruction template uses `{{CAVEMAN_COMMIT_SKILL}}` instead of a
machine-specific username. During installation, this becomes the absolute path
under the current user's home directory (`.agents/skills/caveman-commit/SKILL.md`).
Legacy absolute references to that skill in an existing `AGENTS.md` are corrected
as well, while unrelated paths and custom instructions are preserved. Backups
retain the original instructions. The separate `settings.json` `deviceId` UUID
is preserved, never copied from the repository template or regenerated by this
installer; Pi manages it for fresh installations.

## Git pre-commit check

Enable the repository hook once per checkout:

```powershell
node .githooks/setup.mjs
```

Setup configures only this checkout's `core.hooksPath` and makes the hook
executable. It refuses to replace an existing pre-commit hook or a different
hooks path. If you already manage hooks, add `node .githooks/pre-commit` to your
existing pre-commit hook instead.

The hook compares the **staged** `.pi.user/settings.json` with `HEAD` and blocks
changes to its top-level `deviceId`, including removal of the ID or settings file.
Other settings changes, formatting changes, and unstaged edits are allowed.
Malformed JSON fails the check. Initial commits and the first addition of the
settings file are allowed because there is no committed ID to preserve.

To check manually without creating a commit:

```powershell
node .githooks/pre-commit
```

## Tests

All test files live under [`tests/`](tests/README.md), grouped by component.
Run repository checks with:

```powershell
node --test tests/install.test.mjs tests/install-paths.test.mjs tests/profile-install.test.mjs tests/first-install-profile.test.mjs tests/agents.test.mjs
node --test tests/device-id-hook.test.mjs
npm test --prefix .\pi-custom-commands
npm test --prefix .\pi-guardrails
```
